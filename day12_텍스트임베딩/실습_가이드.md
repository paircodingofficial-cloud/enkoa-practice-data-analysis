# DAY12 텍스트 벡터화·임베딩 — 실습 가이드

오늘 실습은 **문장을 숫자 벡터(임베딩)로 바꾸고, 그 벡터로 유사도·검색·군집·토픽·이미지까지** 다뤄 봅니다.
아래 체크리스트를 **위에서 아래로** 하나씩 끝내세요. 교안(강사와 함께) → 과제(혼자) 순서입니다.

> 차원축소·시각화는 **UMAP 하나**로 합니다(PCA·t-SNE 미사용). 군집(KMeans·엘보우·실루엣)은 **임베딩을 UMAP으로 2차원으로 요약한 좌표 위**에서 합니다.
> 768차원 원본은 노이즈가 커서 실루엣 같은 지표가 잘 안 통하기 때문이에요 — 교안_02에서 이유를 설명합니다.
>
> **함께 따라하기는 시연과 다른 대상을 맡습니다.** 시연이 리뷰 15건을 벡터로 만들면 따라하기는 내가 쓴 문장 2개를,
> 시연이 `'박진감 넘치는 싸움 장면'` 으로 검색하면 따라하기는 `'설레는 첫사랑 이야기'` 로, 시연이 k=3 군집을 보면
> 따라하기는 **새 리뷰가 어느 군집에 들어가는지**를 예측합니다. 코퍼스는 하나로 두되 **묻는 것을 바꾸는** 방식이에요 —
> 임베딩은 하나의 데이터를 유사도 → 검색 → 군집 → 토픽으로 끝까지 관통하는 것이 핵심이라, 중간에 데이터를 바꾸면 흐름이 끊깁니다.

## 1. 교안_01 — 임베딩 기초 (강사와 함께)

- [ ] **데이터 살펴보기** — 영화 리뷰 15건을 `head` 로 먼저 확인
- [ ] **1. 왜 임베딩인가** — 희소 벡터(TF-IDF) vs 밀집 벡터(임베딩) 차이 + **비교 개념도**(겹치는 낱말이 없는 두 로맨스 리뷰: TF-IDF 0.000 vs 임베딩 0.724)
      - 11일차 `TfidfVectorizer` 로 **직접 재보는 셀**이 있습니다 — 0.000 이 실제로 나오는지 확인
      - "겹치는 낱말이 없다"는 **띄어쓰기 기준**입니다(`연인의`·`연인으로` 는 다른 단어로 셈)
- [ ] **2. HuggingFace 임베딩 만들기** — `SentenceTransformer(...).encode(...)` 로 문장→벡터 (따라하기: 내 문장 벡터화)
      - **BERT → 풀링 → SBERT** — 토큰마다 벡터를 만드는 BERT 를 평균(풀링)내 문장 벡터 하나로 만들고, 뜻이 비슷한 쌍이 가까워지도록 추가 학습한 것이 SBERT. 모델명 `ko-**s**roberta` 의 s 가 그것이며, 768이라는 차원도 여기서 나옵니다
- [ ] **3. 코사인 유사도** — `cosine_similarity` 로 두 문장의 뜻이 얼마나 가까운지 + **각도 개념도**(실측 0.724=44도 / 0.493=60도 / 0.227=77도) (따라하기: 직접 재보기)
- [ ] **3-1. 벡터와 수식** — 벡터=숫자의 나열(차원), **내적 $\sum a_ib_i$ · 노름 $\sqrt{\sum a_i^2}$ · 코사인 = 내적÷(길이×길이)** 를 식으로 정의하고 **2차원 손계산**(a=(3,4)·b=(4,3) → 24 / 5·5 / **0.96**, 16.26도)
      - **개념도 2장** — `벡터연산_수식.png`(세 연산 해부) · `코사인_길이무시.png`(방향이 같고 길이만 2배인 d=2a: 내적 50·거리 5.00 인데 **코사인만 1.00**)
      - 라이브러리 없이 파이썬 기본 연산으로 계산한 값이 `cosine_similarity` 와 일치 → **768차원에서도 같은 식**임을 실제 임베딩으로 재확인 (따라하기: 코사인 함수 직접 만들기)
- [ ] **3-2. 유클리드 거리·내적** — 같은 쌍을 **세 가지로** 재어 비교(코사인 0.629 / 거리 9.54 / 내적 76.4)
      - **정렬 방향이 다릅니다** — 코사인·내적은 클수록, 유클리드는 **작을수록** 비슷
      - **정규화 안 한 벡터에서는 순위가 어긋납니다**(이 모델의 벡터 길이는 약 11, 1 이 아님) — 실제로 코사인 순위 ≠ 유클리드 순위
      - **L2 정규화하면 셋이 일치** — 내적 = 코사인, 유클리드 순위 = 코사인 순위 (따라하기: 내 문장쌍을 세 가지로)
- [ ] **4. 의미 검색** — 질문 벡터와 문서들의 유사도로 가장 가까운 문서 찾기 (따라하기: 다른 질문으로 검색)
- [ ] **5. OpenAI Embeddings API** — `client.embeddings.create` 로 **직접 호출**(키 없으면 자동으로 건너뜀) · 1536차원 결과를 HuggingFace 768차원과 비교 · 로컬 vs 상용 표 (따라하기: **키 없이도** 1536차원 배열로 4절 검색 코드가 그대로 도는지 확인)
- [ ] **6. 임베딩 모델 고르기** — HuggingFace 허브 검색·필터(Sentence Similarity + Korean), 모델 카드 읽는 법, **체크리스트**(언어·차원·최대 입력 길이·모델 크기·다운로드·라이선스·용도)
      - **서브워드** — 토큰은 낱말이 아닙니다. `카체이싱이` 는 5조각으로 갈립니다(낱말 6개 리뷰 = 토큰 17개). 128토큰이 생각보다 짧은 이유

## 2. 교안_02 — 군집·토픽·이미지 (강사와 함께)

- [ ] **군집 전에 — UMAP으로 2차원 요약** — 왜 `coords` 위에서 군집하는지 이해하고 `reducer` 객체를 남겨 둠
- [ ] **1. KMeans 군집** — 할당·갱신 두 단계 반복(**3단계 개념도**), 라벨 없이도 장르가 갈리는 교차표 (따라하기: 새 리뷰 예측 — `reducer.transform` 후 `km.predict`)

      - 무게가 전체 분산의 **99.79%** 를 차지 → 표준화 전에는 사실상 **무게로만** 묶인다
      - 표준화하면 **ARI 0.134 → 0.302**(실제 종에 가까워짐), 그런데 **실루엣은 0.608 → 0.456 하락** — 지표 하나만 보면 속는다

- [ ] **3. 실루엣 계수** — a는 작게·b는 크게, 여러 k 비교로 k=3 확인(약 0.93 — UMAP 좌표라 부풀려진 값. 원본 768차원은 0.17) (따라하기: 군집별 평균 실루엣)
- [ ] **4. 대표 키워드(토픽 기초)** — TF-IDF 로 각 군집에 주제 이름 붙이기 (따라하기: 표로 정리)
      - ⚠️ **여기서 한계를 같이 봅니다** — 문서가 3개뿐이라 IDF 가 단어를 구별하지 못해 상위 단어 점수가 대부분 **동률**입니다(서로 다른 IDF 값이 2개). 로맨스 군집 1위가 조사 `두` 인 이유이고, **다음 시간 임베딩 기반 토픽 모델링이 필요한 이유**입니다
- [ ] **5. 이미지 임베딩 — CLIP** — 사진 15장을 **먼저 눈으로 보고** 벡터로, 같은 카테고리끼리 모임 (따라하기: 한 사진과 가장 비슷한 사진)
      - **코사인의 기준선은 모델마다 다릅니다** — CLIP 은 무관한 사진끼리도 0.5 안팎(높으면 0.7 이상), 글↔사진은 맞아도 0.25 안팎. 절대값이 아니라 **상대 크기**를 보세요(실측 같은 카테고리 0.71 vs 다른 0.51)
- [ ] **6. 텍스트-이미지 멀티모달** — 글로 사진 찾기(공유 공간) (따라하기: **한국어 쿼리**로 돌려 영어와 정답 수 비교)

## 5. 과제 LV3 (통합) — 고객 문의, 통합 프로그램 2개

- [ ] 데이터 살펴보기

## 막혔을 때

- **`[자가채점]` 에서 멈춤** — 위 셀 답안 셀의 변수명·값이 문제 지문과 같은지 확인하세요(예: `sim_same`, `best_k`, `coords`).
- **군집 번호가 매번 달라 보임** — 번호(0/1/2) 자체엔 의미가 없어요. 채점은 "같은 군집인지"·"군집 개수"·"대표 키워드"로 합니다. `random_state=0, n_init=10` 을 꼭 고정하세요.
- **실루엣이 이상하게 작음**(0.1~0.2 수준) — 군집을 `emb`(768차원)이 아니라 **`coords`(2차원)** 로 했는지 확인하세요. 교안_02 는 `coords` 에서 약 0.93, 같은 군집을 768차원에서 재면 0.17 입니다.
- **모델 다운로드가 느림** — 처음 한 번만 걸립니다. 네트워크 확인 후 재실행.
- **긴 글인데 유사도가 다 1.00 에 가까움** — `max_seq_length`(이 모델은 **128토큰**)를 넘겨 뒤가 잘린 것입니다. `model.max_seq_length` 로 확인하고, 더 긴 입력을 받는 모델을 쓰거나 문서를 나눠 임베딩하세요.
- **힌트**는 각 문제의 `<details>힌트</details>` 를 펼쳐 보세요(정답 코드가 아니라 풀이 순서 설명).
